20.3 Saída Impressa do texi2any ¶

Para justificar o nome Texinfo-to-any, texi2any tem suporte básico para a criação de saída impressa nos vários formatos: TeX DVI, PDF e PostScript. Isso é feito por meio do método simples de execução do programa texi2dvi quando esses formatos de saída forem solicitados, depois de verificar a validade da entrada para dar para os(as) usuários(as) o benefício da verificação de erros do texi2any. Se você não quiser essa verificação de erros, talvez porque teu manual execute truques avançados do TeX junto com texinfo.tex, basta invocar texi2dvi diretamente.

As opções de formato de saída para isso são --dvi, --dvipdf, --pdf e --ps. Veja-se Formatar com texi2dvi, para mais detalhes acerca dessas opções e operação geral do texi2dvi. Além disso, as opções --verbose, --silent e --quiet são passadas se especificadas; as opções -I e -o são igualmente passadas com os argumentos delas, e --debug sem o argumento dela.

A única opção restante que está relacionada com a invocação do texi2dvi é --Xopt. Aqui, somente o argumento é passado e múltiplas opções --Xopt se acumulam. Isso fornece uma maneira para construir uma linha arbitrária de comando para texi2dvi. Por exemplo, executando 

texi2any --Xopt -t --Xopt @afourpaper --pdf foo.texi

é equivalente a executar 

texi2dvi -t @afourpaper --pdf foo.texi

exceto para verificação de validade.

Embora se possa desejar que outras opções para texi2any tenham efeito, elas não tem. Por exemplo, executar ‘texi2any --no-number-sections --dvi foo.texi’ ainda resulta em um arquivo DVI com seções numeradas. (Talvez isso pudesse ser melhorado no futuro, se solicitações forem recebidas).

O nome real do comando que é invocado é especificado pela variável de personalização TEXI2DVI (veja-se Variáveis de Personalização para Múltiplos Formatos). Como você pode imaginar, o padrão é ‘texi2dvi’.

O próprio texi2any não gera nenhuma saída normal quando invoca texi2dvi, somente mensagens de diagnóstico.
