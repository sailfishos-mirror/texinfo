11.9 Inserindo Unicode: @U ¶

O comando @U{hexadecimal} insere uma representação do caractere Unicode U+hexadecimal. Por exemplo, @U{0132} insere a ligadura holandesa ‘IJ’ (‘Ĳ’).

O valor hexadecimal deveria ter pelo menos quatro dígitos hexadecimais; zeros à esquerda não são adicionados. Em geral, hexadecimal precisa especificar um caractere Unicode normal válido; por exemplo, U+10FFFF (o último ponto de código) é inválido por definição e, portanto, não pode ser inserido dessa forma.

@U é útil para inserir glifos ocasionais para os quais Texinfo não tenha comando dedicado, ao mesmo tempo em que permite que o fonte do Texinfo permaneça puramente ASCII de 7 bits para máxima portabilidade.

Esse comando tem muitas limitações—as mesmas limitações de inserir caracteres Unicode em UTF-8 ou outra forma binária. Primeiro e mais importante, TeX não sabe nada acerca da maioria do Unicode. Suportar glifos adicionais específicos mediante solicitação é possível, mas não é viável para texinfo.tex suportar conjuntos adicionais e inteiros de comandos sequenciados (japonês, urdu, …). O comando @U não faz nada para mudar isso. Se o caractere especificado não for suportado no TeX, um erro será fornecido. A saída do LaTeX tem mais possibilidades em relação ao UTF-8, mas poderia exigir código extra para carregar fontes e para declarar como os caracteres UTF-8 são gerados. (Veja-se @documentencoding codificação: Configurar Codificação de Entrada).

Em HTML e DocBook, a saída proveniente de @U é sempre uma referência de entidade do formato ‘&#xhexadecimal;’, como em ‘&#x0132;’ para o exemplo acima. Isso deveria funcionar mesmo quando um documento HTML usar alguma outra codificação (digamos, Latin 1) e o caractere fornecido não for suportado nessa codificação.

No Info e em texto simples, se a codificação da saída não for UTF-8, a saída será a sequência ASCII ‘U+hexadecimal’, como nos seis caracteres ASCII ‘U+0132’ para o exemplo acima.
