17.3 Detalhes e Ressalvas de Macro ¶

Por projeto, expansão de macro não deveria acontecer nos seguintes contextos:

  • linhas @macro e @unmacro;
  • linhas @if..., incluindo @ifset e similares;
  • @set, @clear, @value;
  • linhas @clickstyle;
  • linhas @end quando não existir expansão de macro no bloco comando.

Infelizmente, TeX pode fazer alguma expansão nessas situações, possivelmente ocasionando erros.

Também, algumas construções relacionadas a macro causam problemas com TeX; algumas das ressalvas estão listadas abaixo. Portanto, se você obtiver erros relacionados a macro ao produzir a versão impressa de um manual, você pode tentar expandir as macros com texi2any invocando texi2dvi com a opção ‘-E’ (veja-se Formatar com texi2dvi). Ou, mais confiavelmente, evite completamente as macros do Texinfo e use uma linguagem projetada para processamento de macros, como M4 (veja-se Processadores Externos de Macro: Diretivas de Linha).

  • Como mencionado anteriormente, os nomes de macro precisam consistir inteiramente de letras.
  • Não é aconselhável redefinir nenhum nome de comando primitivo do TeX, simples ou Texinfo, como uma macro. Infelizmente, esse é um conjunto de nomes grande e aberto, e os possíveis erros resultantes são imprevisíveis.
  • Argumentos para macros recebendo mais que um argumento não podem cruzar linhas.
  • Macros contendo um comando que precise estar em uma linha própria, como um condicional, não podem ser invocadas no meio de uma linha. Similarmente, macros contendo comandos orientados a linha ou texto, como ambientes @example, possivelmente se comportem imprevisivelmente no TeX.
  • Comandos do Texinfo na expansão de uma macro no texto de uma entrada de índice podem acabar sendo tipografados como texto literal (incluindo um sinal “@”), em vez de serem interpretados com o significado pretendido deles.
  • Espaços em branco são ignorados no início das linhas.
  • Macros não podem ser usadas confiavelmente no argumento para comandos de acento (veja-se Inserindo Acentos).
  • Macros deveriam não serem usadas em nomes de nós. Veja-se Escolhendo Nomes de Nós.
  • O escape de barra invertida para vírgulas em argumentos de macro não funciona; @comma{} precisa ser usado.
  • Terminar um corpo de macro com ‘@c’ pode fazer com que o texto seguinte a invocação da macro seja ignorado como um comentário no texi2any. Esse não é o caso ao processar com TeX. Isso frequentemente era feito para “comentar” uma quebra de linha indesejada no final de um corpo de macro, mas isso não mais é necessário, pois, de qualquer maneira, a quebra de linha final antes de ‘@end macro’ não é incluída no corpo da macro.
  • Em geral, você não pode substituir arbitrariamente uma chamada de macro (ou @value) por argumentos de comando do Texinfo, mesmo quando o texto for o mesmo. Texinfo não é M4 (nem mesmo TeX simples). Pode funcionar com alguns comandos, mas falha com outros. É melhor não fazer isso em absoluto. Por exemplo, isto falha: 
    @macro offmacro
off
@end macro
@headings @offmacro

    Isso parece equivalente a @headings off, mas por motivos TeXnológicos, falha com uma misteriosa mensagem de erro (ou seja, ‘Parágrafo terminou antes que @headings estivesse completo’).

  • Expandir macros em um contexto matemático pode conduzir a um espaçamento inadequado na saída do TeX. Por exemplo: 
    @iftex
@macro atan
\\mathop{\\rm atan}
@end macro
@end iftex

@math{@atan{}(x)}

    As chaves seguintes a ‘@atan’ são tratadas pelo TeX como uma subfórmula, conduzindo a espaço extra antes do parêntese de abertura. Você consegue contornar isso definindo uma macro bruta do TeX: 

    @tex
\gdef\atan#1{\mathop{\rm atan}}
@end tex

    O ‘#1’ nessa definição absorve as chaves, de forma que o espaçamento seja o esperado para o objeto \mathop.

  • Se você tiver problemas usando condicionais dentro de uma macro, uma alternativa é a de usar definições separadas de macro dentro de blocos condicionais. Por exemplo, em vez de 
    @macro Mac
@iftex
texto para saída do TeX
@end iftex
@ifnottex
texto para saída não do TeX
@end ifnottex
@end macro

    você pode fazer o seguinte: 

    @iftex
@macro Mac
texto para saída do TeX
@end macro
@end iftex

@ifnottex
@macro Mac
texto para saída não do TeX
@end macro
@end ifnottex
  • Macros não conseguem definir macros na maneira natural. Para fazer isso, você precisa usar condicionais e TeX bruto. Por exemplo: 
    @ifnottex
@macro ctor {nome, arg}
@macro \nome\
algo envolvendo \arg\ de alguma forma
@end macro
@end macro
@end ifnottex
@tex
\gdef\ctor#1{\ctorx#1,}
\gdef\ctorx#1,#2,{\def#1{algo envolvendo #2 de alguma forma}}
@end tex

As seguintes limitações são por projeto:

  • Se você quiser passar um argumento com o comando @, do Texinfo (para produzir uma cedilha, veja-se Inserindo Acentos), você tem de usar @value ou outra solução alternativa. Caso contrário, a vírgula pode ser usada como separadora dos argumentos. Com texi2any, a vírgula pode ser escapada por uma barra invertida. Com TeX, outra solução alternativa precisa ser usada; portanto, nós recomendamos usar essa solução alternativa.

    Por exemplo, 

    @macro mactwo{argprimeiro, argsegundo}
\argprimeiro\+\argsegundo\.
@end macro
@set fc Fran@,cois
@mactwo{@value{fc},}

    produz: 

    François+.
  • @verbatim e macros não se misturam; por exemplo, você não pode iniciar um bloco verbatim dentro de uma macro e terminá-lo fora (veja-se @verbatim: Texto Literal). Iniciar qualquer ambiente dentro de uma macro e terminá-lo fora pode ou não funcionar, para esse desiderato.
  • Macros que definam macros completamente são corretas, mas não é possível ter definições de macro aninhadas incompletamente. Ou seja, @macro e @end macro (da mesma forma para @rmacro) precisam ser pareados corretamente. Por exemplo, você não pode iniciar uma definição de macro dentro de uma macro e, em seguida, terminar essa definição aninhada fora da macro.

Na implementação do makeinfo antes do Texinfo 5.0, os fins de linhas originários da expansão de uma definição do @macro não terminavam um argumento delimitado por linha do comando @ (@chapter, @center, entre outros). Esse não mais é o caso. Por exemplo: 

@macro duaslinhas{}
aaa
bbb
@end macro
@center @duaslinhas{}

No texi2any atual, isso é equivalente a: 

@center aaa
bbb

com apenas ‘aaa’ como o argumento para @center. Na implementação anterior, ele teria sido analisado assim: 

@center aaa bbb
