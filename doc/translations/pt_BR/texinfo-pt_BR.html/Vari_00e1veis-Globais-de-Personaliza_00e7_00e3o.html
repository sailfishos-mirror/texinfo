20.4.4 Variáveis Globais de Personalização ¶

Esta tabela fornece as variáveis de personalização que afetam o comportamento global do texi2any.

CHECK_MISSING_MENU_ENTRY ¶

Quando um bloco @menu ocorrer em um nó, verificar se existe uma entrada de menu para todos os nós subordinados na estrutura de seccionamento do documento. Ligada por padrão.

CHECK_NORMAL_MENU_STRUCTURE ¶

Avisa se os ponteiros do nó (configurados ou explícita ou automaticamente) não estão consistentes com a ordem das entradas do menu do nó. Essa é uma verificação de estrutura mais completa que aquela fornecida por CHECK_MISSING_MENU_ENTRY. Ligada por padrão.

COLLATION_LANGUAGE ¶

Por padrão, texi2any ordena os índices de documentos de acordo com o Algoritmo de Agrupamento Unicode (definido em Padrão Técnico Unicode nº 10), sem adaptação de agrupamento específico do idioma. Se configurado, usar o idioma para adaptação linguística da ordenação de índice.

Atualmente, texi2any não avisa se não existir suporte para adaptação linguística devido ou à ausência de software ou à ausência de suporte para o idioma especificado.

Em Perl, o módulo Unicode::Collate::Locale é usado para adaptação linguística; portanto, se esse módulo não estiver instalado, a variável será ignorada silenciosamente.

Se USE_UNICODE_COLLATION estiver configurada como ‘0’, não existirá agrupamento Unicode e, portanto, também não existirá adaptação linguística.

Veja-se também a variável DOCUMENTLANGUAGE_COLLATION, descrita abaixo.

COMMAND_LINE_ENCODING ¶

Codificação usada para decodificar e codificar argumentos de linha de comando. O padrão é baseado na codificação da localidade. Isso possivelmente afete nomes de arquivos inseridos nos arquivos da saída gerada ou mensagens de erro impressas pelo programa.

Observe que alguns nomes de arquivos e de diretórios provenientes da linha de comando possivelmente não sejam decodificados imediatamente e possivelmente nem mesmo sejam decodificados.

Também é usado para codificar argumentos de linha de comando passados para comandos chamados a partir do texi2any. Por exemplo, latex2html será chamado a partir do texi2any se HTML_MATH estiver configurada como ‘l2h’.

CPP_LINE_DIRECTIVES ¶

Reconhecer diretivas #line em uma passagem de “pré processamento” (veja-se Processadores Externos de Macro: Diretivas de Linha); ligada por padrão.

DEBUG ¶

Se configurada, saída de depuração será gerada; padrão é desligada (zero).

DOC_ENCODING_FOR_INPUT_FILE_NAME ¶

Se configurada, usar as informações de codificação do documento Texinfo de entrada para a codificação de nomes de arquivos de entrada, tais como nomes de arquivos especificados como argumentos @include ou @verbatiminclude. Se desconfigurada, usar a codificação de localidade. O padrão é configurada, exceto no MS-Windows onde a codificação de localidade é usada por padrão.

Observe que isso é somente para nomes de arquivos; a codificação padrão ou @documentencoding é sempre usada para a codificação do conteúdo do arquivo (veja-se @documentencoding codificação: Configurar Codificação de Entrada).

A variável INPUT_FILE_NAME_ENCODING substitui essa variável.

DOC_ENCODING_FOR_OUTPUT_FILE_NAME ¶

Se configurada, usar as informações de codificação do documento Texinfo de entrada para a codificação de nomes de arquivos de saída, tais como arquivos especificados com --output. Se desconfigurada, usar a codificação de localidade. O padrão é desconfigurada, de forma que os nomes dos arquivos serão codificados usando a localidade atual.

Observe que isso é somente para nomes de arquivos; OUTPUT_ENCODING_NAME será usada para a codificação do conteúdo do arquivo.

A variável OUTPUT_FILE_NAME_ENCODING substitui essa variável.

DOCUMENTLANGUAGE_COLLATION ¶

Se configurada, tentar usar o idioma especificado em uma diretiva @documentlanguage para adaptação específica do idioma na ordenação de índice. Veja-se também a variável COLLATION_LANGUAGE, descrita acima. (Veja-se @documentlanguage ll[_cc]: Configurar o Idioma do Documento).

DUMP_STRUCTURE ¶

Para depuração. Se configurada, a árvore construída ao analisar um documento do Texinfo e determinar a estrutura do documento será gerada para o arquivo; se configurada para ‘-’ para erro padrão. Padrão falso.

DUMP_TEXI ¶

Para depuração. Se configurada, nenhuma conversão será feita, somente análise e expansão de macro. Se a opção --macro-expand estiver configurada, o fonte do Texinfo também será expandido para o arquivo correspondente. Padrão falso.

DUMP_TREE ¶

Para depuração. Se configurada, a árvore construída ao analisar um documento do Texinfo será gerada para o arquivo; se configurada para ‘-’ para erro padrão. Para compatibilidade retroativa, para um lançamento, também gera para erro padrão se configurada para ‘1’. Padrão falso.

FORMAT_MENU ¶

Se configurada como ‘menu’, gera menus do Texinfo. Esse é o padrão para Info. ‘sectiontoc’ é a configuração padrão para HTML, onde em vez do conteúdo dos blocos do @menu ser gerado, uma lista de seções subordinadas é gerada em cada nó. Configurar para ‘menu_no_detailmenu’, em vez de ‘menu’ no HTML, se você quiser menus, porém não ‘@detailmenu’ automaticamente gerado no menu mestre do nó Topo. Se configurada como ‘nomenu’, não gera menus.

Essa variável é configurada como ‘nomenu’ ao gerar DocBook ou quando --no-headers for especificada.

IGNORE_SPACE_AFTER_BRACED_COMMAND_NAME ¶

Se configurada, espaços serão ignorados depois de um comando @ que use colchetes. Padrão verdadeiro, correspondendo ao comportamento do TeX.

INPUT_FILE_NAME_ENCODING ¶

Codificação usada para nomes de arquivos de entrada. Essa variável substitui qualquer codificação proveniente do documento ou da localidade atual. Normalmente, você não precisa configurar essa variável, mas ela pode ser usada se os nomes dos arquivos estiverem em uma determinada codificação de caracteres em um sistema de arquivos. Uma alternativa é a de configurar DOC_ENCODING_FOR_INPUT_FILE_NAME como ‘0’ para usar a codificação de localidade. Veja-se também OUTPUT_FILE_NAME_ENCODING.

LOCALE_ENCODING ¶

Codificação de localidade obtida a partir do sistema. Você não deveria precisar configurar explicitamente essa variável.

MAX_MACRO_CALL_NESTING ¶

O número máximo de chamadas recursivas de comandos @ definidos por meio de @rmacro; o padrão é 100000. O propósito dessa variável é o de evitar recursões infinitas.

MESSAGE_ENCODING ¶

Codificação usada para codificar mensagens emitidas pelo texi2any. O padrão é baseado na codificação de localidade.

NO_INDEX ¶

Se configurada, as entradas de índice não são registradas e os comandos @ relacionados aos índices, como @printindex, @synindex ou @defindex não terão efeito. Padrão falso.

NO_USER_COMMANDS ¶

Se configurada, as definições de comando @ definidas por usuário(a) serão ignoradas. @alias, @definfoenclose, @defindex, @macro e comandos @ semelhantes não terão efeito. Padrão falso.

OUTPUT_ENCODING_NAME ¶

Nome normalizado de codificação usado para arquivos de saída gerada. Deveria ser um nome de conjunto de caracteres usável em HTML, tipicamente um dos nomes de codificação preferidos da IANA. Por padrão, se uma codificação de entrada for configurada (tipicamente por meio de @documentencoding), essas informações serão usadas para configurar o nome da codificação da saída gerada, caso contrário, a codificação da saída gerada será baseada na codificação padrão. Veja-se @documentencoding codificação: Configurar Codificação de Entrada.

OUTPUT_FILE_NAME_ENCODING ¶

Codificação usada para nomes de arquivos da saída gerada. Essa variável substitui qualquer codificação originária do documento ou da localidade atual.

Normalmente, você não precisa configurar essa variável, mas ela pode ser usada se nomes de arquivos devessem ser criados em uma determinada codificação de caracteres em um sistema de arquivos. Veja-se também INPUT_FILE_NAME_ENCODING.

PACKAGE ¶
PACKAGE_VERSION ¶
PACKAGE_AND_VERSION ¶
PACKAGE_URL ¶
PACKAGE_NAME ¶

O nome abreviado do pacote da implementação, a versão do pacote, o nome do pacote e a versão concatenada, URL do pacote e o nome completo do pacote, respectivamente. Por padrão, essas variáveis são todas configuradas por meio do Autoconf, Automake e configure.

PREFIX ¶

O prefixo do arquivo da saída gerada, que é preposto a alguns nomes de arquivos de saída gerada. Por padrão, ele é configurado pelo @setfilename ou a partir arquivo de entrada (veja-se Configurando o Nome do Arquivo da Saída Gerada). Como esse valor é usado depende do valor de outras variáveis de personalização ou de opções de linha de comando, como quando a saída gerada for dividida. O padrão é desconfigurada.

PROGRAM ¶

Nome do programa usado. Por padrão, ela está configurada com o nome do programa iniciado, com ‘.pl’ à direita removido.

SORT_ELEMENT_COUNT ¶

Se configurada, o nome de um arquivo para o qual uma lista de elementos (nós ou seções, dependendo do formato da saída gerada) será despejada, ordenada pelo número de linhas que eles contiverem depois da remoção dos comandos @; padrão desconfigurada. Isso é usado pelo programa texi-elements-by-size no diretório util/ da distribuição do fonte do Texinfo (veja-se texi-elements-by-size).

SORT_ELEMENT_COUNT_WORDS ¶

Ao despejar o arquivo de elementos por tamanho (veja-se o item anterior), usar contagens de palavras em vez de contagens de linhas; padrão falso.

TEST ¶

Se configurada como um número inteiro positivo, algumas variáveis que normalmente são geradas dinamicamente novamente para cada execução (data, nome do programa, versão) serão configuradas como valores fixos e fornecidos. Alguns nomes de arquivos também podem ter a parte de diretório removida. Também pode ser selecionado código que forneça resultados mais reproduzíveis. Isso é útil para comparar a saída gerada com um arquivo de referência, como é feito para os testes. Recursos não selecionados no caso padrão, mas interessantes para testes, também estarão habilitados. Por exemplo, código relacionado à liberação de memória e a verificações de memória liberada. Se o valor for maior, mais verificações serão habilitadas, o que pode exigir a instalação de módulos Perl adicionais. O padrão é indefinida.

TEXINFO_OUTPUT_FORMAT ¶

O formato de saída gerado. Configurar a partir da linha de comando com opções como --html, como o valor da variável de ambiente TEXINFO_OUTPUT_FORMAT (veja-se Variáveis de Ambiente Reconhecidas pelo texi2any) ou como uma opção de personalização. Veja-se Seleção do Formato de Saída.

O valor configurado na variável TEXINFO_OUTPUT_FORMAT é em geral o mesmo que o nome usado para configurar o formato, mas nem sempre. Se o formato for configurado como xml, com --xml, com a variável de ambiente TEXINFO_OUTPUT_FORMAT ou com uma variável de personalização, a variável de personalização TEXINFO_OUTPUT_FORMAT será configurada com um nome de formato de saída mais específico texinfoxml. Esse tipo de diferença na nomenclatura deveria não ter nenhuma consequência visível para o(a) usuário(a).

TREE_TRANSFORMATIONS ¶

O valor associado é uma lista separada por vírgulas de transformações que podem ser aplicadas à árvore do Texinfo antes se gerar o resultado. Se mais que um for especificado, o ordenamento será irrelevante; cada um será sempre aplicado no ponto necessário durante o processamento.

Por padrão, as transformações de árvore ‘move_index_entries_after_items’ e ‘relate_index_entries_to_table_entries’ são executadas para saída HTML e DocBook. Aqui está um exemplo de atualização do menu mestre em um documento: 

texi2any \
  -c TREE_TRANSFORMATIONS=regenerate_master_menu \
  -c TEXINFO_OUTPUT_FORMAT=plaintexinfo \
  meudoc.texi \
  -o /tmp/saida

(Advertência: como a saída de ‘plaintexinfo’ expande macros e condicionais do Texinfo, é necessário remover quaisquer dessas diferenças antes de se instalar as atualizações no documento original. Isso possivelmente seja remediado em um lançamento futuro).

As seguintes transformações são atualmente suportadas (muitas são usadas no utilitário pod2texi distribuído com Texinfo; veja-se Invocando pod2texi: Converter Pod para Texinfo):

‘complete_tree_nodes_menus’ ¶

Adicionar entradas de menu ou menus inteiros para nós associados com seções de qualquer nível, com base na árvore de seccionamento.

‘complete_tree_nodes_missing_menu’ ¶

Adicionar menus inteiros para nós associados com seções sem menu. Os menus são baseados na árvore de seccionamento.

‘fill_gaps_in_sectioning’ ¶

Adiciona seções @unnumbered... vazias em uma árvore para preencher lacunas no seccionamento. Por exemplo, um @unnumberedsec será inserido se um @chapter for seguido por um @subsection.

‘insert_nodes_for_sectioning_commands’ ¶

Inserir nós para comandos de seccionamento carecentes de um nó correspondente.

‘move_index_entries_after_items’ ¶

Em @enumerate e @itemize, mover entradas de índice que aparecem logo antes de @item para logo depois de @item. Linhas de comentários entre entradas de índice também serão movidas. Conforme mencionado, isso sempre é feito para saída HTML e DocBook.

‘regenerate_master_menu’ ¶

Atualizar o menu mestre do nó Top, ou substituindo o (primeiro) @detailmenu no menu do nó Top ou criando-o no final do menu do nó Top.

‘relate_index_entries_to_table_entries’ ¶

Em @table, @vtable e @ftable, reassociar as informações de entrada do índice originárias de um comando @ de índice que aparece logo depois uma linha @item com o primeiro elemento do @item. Remover o comando @ de índice da árvore.

USE_SETFILENAME_EXTENSION ¶

O padrão é ativado para Info e desativado para outras saídas. Se configurada, usar exatamente o que @setfilename fornecer para o nome do arquivo da saída gerada, incluindo a extensão. Você não deveria precisar configurar explicitamente essa variável.

USE_UNICODE_COLLATION ¶

Por padrão, texi2any ordena os índices de documentos de acordo com o Algoritmo de Agrupamento Unicode (definido em Padrão Técnico Unicode nº 10), que realiza uma ordenação multi-nível de sequências de caracteres contendo pontos de código Unicode. (Para fazer isso, o programa usa o módulo Unicode::Collate, uma parte padrão das instalações Perl). No entanto, o uso desse algoritmo incorre em tempos de execução notavelmente mais longos ao processar manuais com índices grandes.

Configure essa variável como ‘0’ para usar um algoritmo de ordenação mais simples e mais rápido.

Você pode achar isso útil para acelerar o texi2any se você não tiver muitos caracteres não-ASCII no texto de entrada do índice ou se não se importar em ter os índices ordenados corretamente, especialmente ao trabalhar no rascunho de um manual.

USE_UNIDECODE ¶

Se configurada como falso, não usar o módulo Perl Text::Unidecode para transliterar mais caracteres provenientes do código Perl; padrão verdadeiro.
