14.8 Convenções para Escrita de Definições ¶

Um manual não precisa e não deveria conter mais que uma definição para um determinado nome. Um apêndice contendo um resumo deveria usar @table em vez dos comandos de definição.

Quando você escrever uma definição usando @deffn, @defun ou um dos outros comandos de definição, por favor, tome cuidado para usar argumentos que indiquem o significado, como com o argumento count para a função forward-word. Além disso, se o nome de um argumento contiver o nome de um tipo, como integer, tome cuidado para que o argumento seja realmente desse tipo.

Fontes. Como Texinfo é uma linguagem semântica, você quase nunca precisará especificar estilos de fonte com comandos explícitos de fonte em definições (veja-se Fontes para Impressão). No entanto, você possivelmente precise contornar problemas com formatos de saída e (ou) construções específicos. Aqui estão algumas possibilidades:

  • Marcando explicitamente uma palavra-chave da Lisp, como ‘&keyword’, com @r{&keyword}, produzindo &keyword.

    Observe que tais palavras-chave em argumentos de definição são (atualmente) renderizadas em romano no TeX, mas essa formatação não é feita em nenhum outro formato de saída.

  • ‘@r{@slanted{argumento}}’, produzindo argumento, semelhante a @var, mas evitando maiusculizar o argumento dele na saída do Info.

    Neste e no ponto anterior, @r reconfigura a fonte daquela sendo usada no contexto da linha de definição (inclinada ou de máquina de escrever) para um estilo romano vertical.

  • Você poderia usar @t (ou até mesmo ‘@r{@t{…’, usando @r para reconfigurar estilos de fonte) para marcar sintaxe literal em uma linha de definição onde, de outra maneira, o texto seria gerado no estilo romano inclinado. @code seria inapropriado aqui, pois ele adiciona aspas na saída do Info.

Algum grau de tentativa e erro possivelmente seja necessário para obter o resultado que você quer. Como sempre, como comandos aninhados de fonte se combinam depende do formato de saída, de forma que deveria ser evitada onde possível.

Esperançosamente, tais usos sejam mantidos ao mínimo. Uma possibilidade é a de envolucrá-los em @macro (veja-se Definindo Novos Comandos do Texinfo), permitindo que esses usos sejam facilmente mudados no futuro.
