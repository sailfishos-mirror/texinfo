22.7.4 Expansão do Caractere de 8 Bits da Referência Cruzada do HTML ¶

Normalmente, caracteres diferentes do ASCII simples de 7 bits são transformados no(s) correspondente(s) ponto(s) de código do Unicode na Forma de Normalização C, a qual usa caracteres pré-compostos quando disponíveis. (Essa é a forma de normalização recomendada pelo W3C e outros órgãos). Isso vale quando esse ponto de código for 0xffff ou menos, como quase sempre é.

Eles serão então transformados pelas regras acima na sequência de caracteres ‘_hhhh’, onde hhhh é o ponto de código em hexadecimal.

Por exemplo, combinando essa regra e a seção anterior: 

@node @b{A} @TeX{} @u{B} @point{}@enddots{}
⇒ A-TeX-B_0306-_22C6_002e_002e_002e

Aviso: 1) @enddots se expande para três pontos os quais, por sua vez, se expandem para três ‘_002e’s; 2) @u{B} é um ‘B’ com acento breve, o qual não existe como um caractere pré-acentuado do Unicode, portanto se expande para ‘B_0306’ (B com combinação de breve).

Quando o ponto de código do Unicode estiver acima de 0xffff, a transformação será ‘__xxxxxx’, ou seja, dois sublinhados iniciais seguidos por seis dígitos hexadecimais. Como o Unicode declarou que o ponto de código mais alto deles é 0x10ffff, isso é suficiente. (Nós achamos que era melhor definir esse escape extra que usar sempre seis dígitos hexadecimais, já que os dois primeiros seriam quase sempre zeros).

Esse método funciona bem se o nome do nó consistir principalmente de caracteres ASCII e contiver somente alguns de 8 bits. Mas se o documento for escrito em um idioma cuja escrita não seja baseada no alfabeto latino (por exemplo, ucraniano), ele criará nomes de arquivos que consistem quase inteiramente de notações ‘_xxxx’, o que é inconveniente e quase ilegível. Para lidar com esses casos, texi2any oferece a opção de linha de comando --transliterate-file-names. Essa opção habilita transliteração de nomes de nós em caracteres ASCII para fins de criação de nomes de arquivos. A transliteração é baseada em princípios fonéticos, o que torna os nomes dos arquivos gerados mais facilmente compreensíveis.

Para a definição da Forma de Normalização C do Unicode, veja-se o informe UAX#15 do Unicode, http://www.unicode.org/reports/tr15/. Muitos documentos e implementações relacionados estão disponíveis em outros lugares na web.
