19.2 Formatar com texi2dvi ou texi2pdf ¶

O programa texi2dvi se encarrega de todas as etapas para produzir um arquivo DVI do TeX a partir de um documento do Texinfo. Similarmente, texi2pdf produz um arquivo PDF9.

Para executar texi2dvi ou texi2pdf sobre um arquivo de entrada foo.texi, faça isto (onde ‘prompt$ ’ é o prompt do teu shell): 

prompt$ texi2dvi foo.texi
prompt$ texi2pdf foo.texi

Conforme mostrado nesse exemplo, os nomes dos arquivos fornecidos para texi2dvi e texi2pdf precisam incluir alguma extensão, como ‘.texi’.

Para uma lista de todas as opções, execute ‘texi2dvi --help’. Algumas das opções são discutidas abaixo.

Com a opção --pdf, texi2dvi produz saída PDF em vez de DVI, executando pdftex em vez de tex. Alternativamente, o comando texi2pdf é uma abreviação para executar ‘texi2dvi --pdf’. O comando pdftexi2dvi também é fornecido como uma conveniência para AUC-TeX (veja-se AUC-TeX, pois ele prefere meramente antepor ‘pdf’ às ferramentas de produção de DVI para ter ferramentas de produção de PDF.

Com a opção --dvipdf, texi2dvi produz saída PDF executando TeX e então um programa DVI-para-PDF: se a variável de ambiente DVIPDF estiver configurada, esse valor será usado, senão o primeiro programa existente entre dvipdfmx, dvipdfm, dvipdf, dvi2pdf, dvitopdf. Esse método geralmente suporta melhor a tipografia CJK que o pdftex.

Com a opção --ps, texi2dvi produz PostScript em vez de DVI, executando tex e então dvips (veja-se Dvips). (Ou o valor da variável de ambiente DVIPS, se configurada).

texi2dvi também pode ser usado para processar arquivos do LaTeX. Normalmente, texi2dvi é capaz de adivinhar a linguagem do arquivo de entrada pelo conteúdo e extensão de nome de arquivo dele; no entanto, se ele adivinhar errado, você consegue especificar explicitamente a linguagem de entrada usando a opção de linha de comando --language=linguagem, onde linguagem é ou ‘latex’ ou ‘texinfo’.

Uma opção útil para texi2dvi é ‘--command=comando’. Isso insere comando em uma linha própria no início de um arquivo em uma cópia temporária do arquivo de entrada, antes de executar o TeX. Com isso, você pode especificar diferentes formatos de impressão, tais como @smallbook (veja-se @smallbook: Imprimindo Livros “Pequenos”), @afourpaper (veja-se Imprimir em Papel A4) ou @pagesizes (veja-se @pagesizes [largura][, altura]: Tamanhos Personalizados de Página), sem realmente mudar o fonte do documento. (Você também pode fazer isso em todo o site com texinfo.cnf; veja-se Preparando para TeX).

A opção -E (equivalentemente, -e e --expand) faz a expansão de macro do Texinfo usando texi2any em vez da implementação do TeX (veja-se Detalhes e Ressalvas de Macro). Cada implementação tem limitações e vantagens próprias delas.

texi2dvi recebe a opção --build=modo para especificar onde a compilação do TeX acontece e, como consequência, como os arquivos auxiliares são tratados. O modo de construção também pode ser configurado usando-se a variável de ambiente TEXI2DVI_BUILD_MODE. Os valores válidos para modo são:

‘local’

Compile no diretório atual, deixando todos os arquivos auxiliares por aí. Esse é o uso tradicional do TeX.

‘tidy’

Compile em um diretório local *.t2d, onde os arquivos auxiliares são deixados. Os arquivos de saída são copiados de volta para o arquivo original.

Usar o modo ‘tidy’ traz várias vantagens:

  • o diretório atual não fica abarrotado com uma abundância de arquivos temporários.
  • a desordem pode ser reduzida ainda mais usando-se --build-dir=diretório: todos os diretórios *.t2d ficam armazenados lá.
  • a desordem pode ser reduzida a zero usando-se, por exemplo, --build-dir=/tmp/\$USER.t2d ou --build-dir=\$HOME/.t2d.
  • o arquivo da saída gerada é atualizado depois de cada execução bem-sucedida do TeX, por para fins de visualização concorrente da saída gerada. Em uma construção ‘local’, o visualizador para durante a execução inteira do TeX.
  • se a compilação falhar, o estado anterior do arquivo da saída gerada será preservado.
  • As compilações de PDF e de DVI são mantidas em separado subdiretórios, evitando qualquer possibilidade de incompatibilidade dos arquivos auxiliares.

Por outro lado, como a compilação ‘tidy’ ocorre em outro diretório, ocasionalmente o TeX não conseguirá encontrar alguns arquivos (por exemplo, ao usar \graphicspath): nesse caso, use -I para especificar os diretórios adicionais a considerar.

‘clean’

O mesmo que ‘tidy’, mas remove o diretório auxiliar depois. Cada compilação, portanto, exige o ciclo completo.

texi2dvi usará etex se estiver disponível, porque ele executa mais rápido em alguns casos e fornece informações adicionais de rastreamento ao depurar texinfo.tex. No entanto, essa versão estendida do TeX não é exigida, e a saída DVI é idêntica.

texi2dvi tenta detectar arquivos auxiliares gerados pelo TeX, seja usando a opção -recorder seja procurando por ‘\openout’ no arquivo de registro que uma execução do TeX produzir. Você pode controlar como texi2dvi faz isso com a variável de ambiente TEXI2DVI_USE_RECORDER. Os valores válidos são:

‘yes’

use a opção -recorder, sem verificações.

‘no’

procure por ‘\openout’ no arquivo de registro, sem verificações.

‘yesmaybe’

verifique se a opção -recorder é suportada e, se sim, use-a; caso contrário, verifique se o rastreamento de ‘\openout’ no arquivo de registro é suportado e, se sim, use-o; caso contrário, será um erro.

‘nomaybe’

o mesmo que ‘yesmaybe’, exceto que o rastreamento de ‘\openout’ no arquivo de registro é verificado primeiro.

O padrão é ‘nomaybe’. Essa variável de ambiente é fornecida para fins de solução de problemas e possivelmente mude ou desapareça no futuro.

Notas de Rodapé

(9)
