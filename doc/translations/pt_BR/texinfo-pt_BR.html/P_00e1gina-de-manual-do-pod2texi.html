20.6.1 pod2texi ¶

NOME do pod2texi ¶

pod2texi - converter Pod para Texinfo

SINOPSE do pod2texi ¶

  pod2texi [OPÇÃO]... POD...

DESCRIÇÃO do pod2texi ¶

Traduzir arquivo(s) Pod para Texinfo. Existem dois modos básicos de operação. Primeiro, por padrão, cada Pod é traduzido para um manual Texinfo independente.

Segundo, se --base-level for configurado como superior a 0, cada Pod será traduzido para um arquivo adequado para @include, e mais um arquivo com um menu principal e todo o @include será gerado.

OPÇÕES do pod2texi ¶

--appendix-sections

Usar comandos de seccionamento de apêndice (@appendix, ...) em vez dos comandos @ padrão do Texinfo de seccionamento numerados (@chapter, @section, ...).

--base-level=NUM|NOME

Configura o nível dos comandos head1. Pode ser um inteiro ou um comando do Texinfo de seccionamento (sem o @): 1 corresponde ao nível @chapter/@unnumbered, 2 ao nível @section e assim por diante. O padrão é 0, significando que os comandos head1 ainda são produzidos como capítulos, mas a saída gerada é organizada como um manual independente.

Se o nível não for 0, o arquivo Pod será renderizado como um fragmento de um manual Texinfo adequado para @include. Nesse caso, cada arquivo Pod terá um comando de seccionamento adicional cobrindo o arquivo inteiro, um nível acima do valor --base-level. Portanto, para transformar cada arquivo Pod em um capítulo de um manual grande, você deveria usar section como o nível base.

Para um exemplo de como transformar o Texinfo a partir da própria documentação do Perl, veja-se contrib/perldoc-all na distribuição do fonte do Texinfo.

--debug=NUM

Configurar nível de depuração como NUM.

--generate-setfilename

Gerar uma linha @setfilename para manuais independentes. Pode ser negado com --no-generate-setfilename. Ignorado se --base-level não for 0.

--headings-as-sections

Usar comandos de cabeçalhos (@heading, ...) em vez dos comandos @ padrão do Texinfo de seccionamento numerados (@chapter, @section, ...). O comando de seccionamento que cobre o arquivo inteiro gerado para cada arquivo Pod se --base-level não for 0 é um comando numerado.

--help

Exibir ajuda e sair.

--menus

Gerar menus do nó. Se existir um manual principal, o menu do nó Superior dele será sempre gerado, pois um menu mestre será gerado. Outros menus de nós não são gerados no caso padrão.

--outdir=NOME

Se existir um manual principal com arquivos de inclusão (cada um correspondendo a um arquivo Pod de entrada), então os arquivos Texinfo gerados serão colocados no diretório NOME. O padrão é baseado em --subdir.

--output=NOME

Nome para o primeiro manual ou para o manual principal, se existir um manual principal. O padrão é o de escrever na saída padrão.

--no-section-nodes

Usar âncoras para seções em vez de nós.

--no-fill-section-gaps

Não preencher lacunas de seccionamento com arquivos @unnumbered vazios. Normalmente, é bom manter intacta a hierarquia de seccionamento.

--preamble=STR

Inserir STR como padrão superior antes do menu e de inclusões. Se STR for configurado como -, ler o padrão superior a partir da entrada padrão. O padrão superior é um início mínimo para um documento do Texinfo.

--setfilename=STR

Usar STR no padrão superior antes do menu e de inclusões para @setfilename para o manual principal, se --base-level não estiver configurado como 0. Ignorado se --base-level for 0. Nenhum @setfilename será gerado no caso padrão para o manual principal.

--subdir=NOME

Se existir um manual principal com arquivos de inclusão (cada um correspondendo a um arquivo Pod de entrada), então esses arquivos de inclusão serão incluídos a partir de NAME.

Se --outdir for configurado, NOME deveria, em geral, ser configurado para o diretório relativo entre o manual principal e o argumento --outdir.

--unnumbered-sections

Usar comandos de seccionamento não numerados (@unnumbered, ...) em vez dos comandos @ de seccionamento numerados padrão do Texinfo (@chapter, @section, ...).

--top=TOP

Nome do elemento @top para o manual principal. Pode conter código Texinfo.

--version

Exibir informações da versão e sair.
