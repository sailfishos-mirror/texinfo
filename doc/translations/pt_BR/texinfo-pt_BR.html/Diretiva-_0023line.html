17.7.1 Diretiva ‘#line’ ¶

Uma linha de entrada como esta: 

#line 100 "foo.ptexi"

indica que a próxima linha foi linha 100 do arquivo foo.ptexi, e, portanto, isso é ao que uma mensagem de erro deveria se referir. Tanto M4 (veja-se Recursos de preprocessador em GNU M4) quanto CPP (veja-se Controle de Linha em O Preprocessador C e Saída de Preprocessador em O Preprocessador C) conseguem gerar tais linhas.

O programa texi2any reconhece essas linhas por padrão, exceto dentro dos blocos @verbatim (veja-se @verbatim: Texto Literal). O reconhecimento delas pode ser desativado completamente com CPP_LINE_DIRECTIVES (veja-se Variáveis Globais de Personalização), embora normalmente não exista razão para fazer isso.

Para aqueles poucos programas (M4, CPP, Texinfo) que precisem documentar diretivas ‘#line’ e, portanto, tem exemplos que, de outra forma, corresponderiam ao padrão, o comando @hashchar{} pode ser usado (veja-se Inserindo ‘#’ com @hashchar{}). A linha de exemplo acima se parece com isto no fonte para este manual: 

@hashchar{}line 100 "foo.ptexi"

O comando @hashchar foi adicionado ao Texinfo em 2013. Se você não quiser depender dele, você também pode usar @set e @value para inserir o literal ‘#’: 

@set hash #
@value{hash}line 1 "exemplo.c"

Ou, se adequado, um ambiente @verbatim pode ser usado em vez de @example. Como mencionado acima, o reconhecimento de #line é desabilitado dentro de blocos verbatim.
