22.8.1 Personalização da Estrutura da Saída Gerada HTML ¶

Você consegue usar variáveis de personalização para controlar a saída gerada de títulos e de sumários de documentos ou de outras partes semelhantes de documentos. Outras variáveis afetam como texi2any visualiza a estrutura de um documento e como a saída gerada é dividida em arquivos da saída gerada.

Se SHOW_TITLE for ‘undef’, o padrão, nenhum título será gerado no início da saída gerada. Se você configurar essa variável, por padrão o conteúdo de @titlepage (ou a saída gerada a partir de @maketitle) será usado para o título; desconfigure USE_TITLEPAGE_FOR_TITLE para obter uma sequência simples de caracteres de título.

Por padrão, a saída gerada HTML é adaptada para visualização on-line, com o nó Topo sendo gerado como um ponto de partida de nível superior para o leitor. Você pode configurar NO_TOP_NODE_OUTPUT para remover o nó Topo, o que resulta em saída gerada que pode ser mais semelhante ao formato de um livro impresso. Por padrão, configurar-se NO_TOP_NODE_OUTPUT também gera um título no início do documento, embora você consiga substituir isso configurando SHOW_TITLE como 0.

Em cada nó, por padrão, uma lista de seções subordinadas é gerada para navegação. Isso corresponde à variável FORMAT_MENU sendo configurada como ‘sectiontoc’. Para usar menus para navegar no documento (como no formato Info; veja-se Menus), configure FORMAT_MENU como ‘menu’. Configure FORMAT_MENU como ‘menu_no_detailmenu’ se você quiser menus, mas nenhum @detailmenu gerado automaticamente para o menu mestre Topo. Se você não quiser que ou menus ou listas de seções subordinadas para navegação sejam exibidas, configure FORMAT_MENU como ‘nomenu’.

Por padrão, o sumário para o documento inteiro é gerado no final da seção @top, para ter o local principal para navegação no documento inteiro desde o início. Isso corresponde à variável CONTENTS_OUTPUT_LOCATION configurada como ‘after_top’.

Você consegue ter o sumário gerado depois do título (se SHOW_TITLE estiver configurada) configurando CONTENTS_OUTPUT_LOCATION como ‘after_title’. Para gerar o sumário no final do documento ou em um arquivo separado, se a saída gerada for dividida, configure CONTENTS_OUTPUT_LOCATION como ‘separate_element’. Você também pode configurar CONTENTS_OUTPUT_LOCATION como ‘inline’: nesse caso, o sumário será gerado onde o comando @ correspondente, por exemplo @contents, for usado.

Você pode achar útil configurar CONTENTS_OUTPUT_LOCATION quando FORMAT_MENU estiver configurada como ‘menu’ para a finalidade de usar menus para navegação. Nesse caso, já deveria existir um menu mestre na seção @top (veja-se Partes de um Menu Mestre), e assim o leitor do teu manual possivelmente não precise de um sumário no mesmo local.

Por padrão, cada nó é gerado em um arquivo separado. Você consegue mudar isso com a opção de linha de comando --split, que é equivalente a configurar a variável SPLIT. SPLIT pode assumir os valores ‘chapter’, ‘section’ ou ‘node’ ou ser configurada como uma sequência vazia de caracteres para indicar saída não dividida. Veja-se Dividindo Saída Gerada.

Unidades elementares chamadas unidades de saída são usadas para saída, com cada arquivo de saída contendo o conteúdo de uma ou mais unidades de saída, dependendo do valor de SPLIT. As unidades de saída contêm o conteúdo associado a um nó ou comando de seccionamento. Em fontes típicas de documentos Texinfo, um comando de nó é quase sempre associado com um comando de seccionamento imediatamente seguinte.

A variável de personalização USE_NODES determina se o nó ou o comando de seccionamento é considerado o comando principal. Por padrão, nós são usados como o componente principal para a separação das unidades da saída gerada. Você consegue configurar USE_NODES como falso para usar preferencialmente seccionamento para decidir onde as unidades da saída gerada serão separadas. Quando seções forem os componentes principais das unidades da saída gerada, nós “isolados” não diretamente associados com um comando de seccionamento serão associados com o comando de seccionamento seguinte, enquanto comandos de seccionamento sem nós constituem unidades da saída gerada. Por outro lado, quando nós forem os principais componentes das unidades da saída gerada, seções isoladas não associadas com nós serão associadas com o nó anterior e nós isolados serão unidades da saída gerada.

Por padrão, a configuração de USE_NODES também afeta se os linques Próximo, Acima e Anterior nos cabeçalhos dos nós lincam-se a nós ou a seções, com os nós usados se verdadeira e as seções usadas se falsa. Você consegue substituir isso usando a variável USE_NODE_DIRECTIONS (o valor padrão é indefinido). Observe que essa configuração não determina a sequência de caracteres do linque, somente para onde os linques apontam; veja-se xrefautomaticsectiontitle para a personalização da sequência de caracteres do linque. Se os nós e as seções estiverem sistematicamente associados, essa personalização não terá efeito prático.

Você pode adicionar um elemento especial Sobre, explicando como navegar, configurando DO_ABOUT; configurada como 0 no caso padrão (sem elemento Sobre). Se PROGRAM_NAME_IN_ABOUT também estiver configurada, produz o nome do programa e diversas informações relacionadas no elemento especial Sobre; padrão falso.

No caso de saída gerada não dividida, por padrão, somente um arquivo é gerado, o qual contém quaisquer elementos Sobre (com DO_ABOUT) e elementos de sumário (com CONTENTS_OUTPUT_LOCATION configurada como ‘separate_element’). Se você preferir que esses elementos especiais sejam separados, configure MONOLITHIC como 0 para gerar elementos especiais em arquivos separados.
