22.8.2 Personalização de Nomes de Arquivo e de Linques para HTML ¶

Existem variáveis de personalização para controlar os nomes dos arquivos da saída gerada e para personalizar a saída de hiperlinques dentro dos arquivos da saída gerada.

Você consegue especificar os nomes dos arquivos de saída com mais controle que meramente a opção de linha de comando --output (veja-se Invocando texi2any a partir de um Shell). A variável de personalização PREFIX substitui o nome base do arquivo fornecido por @setfilename, ou o nome do arquivo, e deveria não conter quaisquer componentes de diretório. Para alterar diretórios intermediários, use a variável de personalização SUBDIR. Finalmente, você também pode substituir a extensão com a variável de personalização EXTENSION. Essa variável deveria ser undef se nenhuma extensão for para ser adicionada. Se você configurar CASE_INSENSITIVE_FILENAMES, os nomes dos arquivos serão construídos como se o sistema de arquivos fosse insensível a maiúsculas e minúsculas. Nesse caso, um nome de arquivo será usado para todos os arquivos, diferindo somente por maiúsculas e por minúsculas.

Além disso, a variável de personalização TOP_FILE substitui o nome do arquivo da saída gerada para o elemento superior. Isso, em geral, só é levado em conta quando a saída gerada for dividida.

Se USE_ACCESSKEY estiver configurada, o atributo accesskey será usado para fornecer atalhos de teclado em alguns hiperlinques de navegação. n é usado para linques para o próximo nó ou seção, p para linques para o nó ou seção anterior e u para linques de direção ascendente. No caso padrão, o valor dessa variável de personalização é undef e configurado automaticamente baseado na divisão do documento de saída, para evitar configurar accesskey para vários valores na mesma página HTML (veja-se Dividindo HTML).

Existem variáveis de personalização que são específicas para tipos particulares de linques:

Linques de comandos de referência cruzada ¶

Se o segundo argumento de um comando de referência cruzada estiver configurado, ele será exibido como texto de hiperlinque (veja-se @xref com Dois Argumentos). Caso contrário, a variável de personalização XREF_USE_NODE_NAME_ARG será usada para determinar o texto do hiperlinque. Se configurado como 1, usar o (primeiro) argumento do nome do nó em comandos @ de referência cruzada para o texto exibido como o hiperlinque. Se configurado como 0, usar o nome do nó se USE_NODES estiver configurada; caso contrário, o nome da seção. Se configurado como ‘undef’, usar o primeiro argumento em ambientes pré-formatados, caso contrário, usar o nome do nó ou o nome da seção dependendo de USE_NODES. O padrão é ‘undef’.

Linques para flutuações ¶

Se você configurar XREF_USE_FLOAT_LABEL(padrão é desligada), o rótulo flutuante será usado em vez do tipo seguido pelo número flutuante (veja-se @float [tipo][,rótulo]: Material Flutuante).

Linques para nós ou para seções para entradas de índice ¶

Na formatação de @printindex, dois linques são gerados: um linque para a entrada do índice e um linque para o comando @ raiz que contém a entrada do índice. A variável de customização NODE_NAME_IN_INDEX especifica se o nó ou seção deveria ser usado para o linque para o comando @ raiz. Se verdadeiro, usar nomes de nós nas entradas de índice; caso contrário, usar nomes de seção. Se indefinido, usar o valor de USE_NODES para determinar qual comando @ raiz preferir. O padrão é indefinido.

Linques de menu ¶

Os nomes dos nós são usados em linques de entradas de menu por padrão. Configurar NODE_NAME_IN_MENU como falso para usar nomes de seção.

Linques de sumário ¶

Se um Sumário principal e um Sumaríssimo estiverem presentes, as referências cruzadas no Sumaríssimo se lincarão às correspondentes entradas do Sumário no caso padrão. Configurar SHORT_TOC_LINK_TO_TOC como 0 para lincar aos comandos de seccionamento.

Se você configurar TOC_LINKS, linques de títulos para entradas do sumário serão criados; padrão falso.

Linque de direção Acima do nó Topo ¶

Por padrão, nenhuma referência Acima é gerada para o nó Topo. Você pode configurar IGNORE_REF_TO_TOP_NODE_UP para que quaisquer referências para o nó Acima de Topo (por padrão, ‘(dir)’) que aparecem em outras referências cruzadas também sejam ignoradas. IGNORE_REF_TO_TOP_NODE_UP não está configurada no caso padrão. (Veja-se TOP_NODE_UP).

Se o manual estiver referenciado em uma página web juntamente com outros manuais, possivelmente seja relevante lincar para essa página. Configure TOP_NODE_UP_URL como o URL usado para nó Topo que Acima referenciar. Se TOP_NODE_UP_URL for configurada, o valor de TOP_NODE_UP será usado para o texto do hiperlinque, com ‘(dir)’ como padrão. TOP_NODE_UP pode ser usada no atributo, portanto deveria não conter nenhum elemento.

Por exemplo, no projeto GNU https://www.gnu.org/manual/ coleta linques para a maioria dos manuais GNU; portanto, TOP_NODE_UP_URL é melhor especificada como /manual/ se o manual for instalado em www.gnu.org.

Veja-se O Primeiro Nó para mais acerca dos ponteiros do nó Topo.

linques de imagens ¶

Se IMAGE_LINK_PREFIX estiver configurada, o valor associado será preposto aos linques do arquivo de imagem; padrão desconfigurada. Isso poderia ser útil se arquivos de imagens estiverem em um subdiretório específico.

As referências cruzadas entre manuais HTML são especificadas precisamente (veja-se Referências Cruzadas do HTML). A personalização de locais de manuais é fornecida por meio dos arquivos htmlxref.cnf e htmlxref.d/*.cnf (veja-se Configuração de Referência Cruzada do HTML).

Diretórios e nomes de arquivo padrão são usados para referenciar cruzadamente manuais alvo não encontrados por meio da Configuração do Xref do HTML (veja-se Básicos do Linque de Referência Cruzada do HTML). Por padrão, um aviso é fornecido para cada manual externo que não esteja nos arquivos de configuração do Xref do HTML. Se não quiser avisos acerca de tais manuais, você deveria configurar CHECK_HTMLXREF como ‘0’. Isso poderia ser relevante, por exemplo, se você souber que os manuais estão instalados localmente.

Você consegue usar variáveis de personalização para especificar a Configuração do Xref do HTML mais precisamente. Por padrão, o nome do arquivo usado para configuração do Xref do HTML e o diretório htmlxref.d são pesquisados em diretórios, arquivos em htmlxref.d com a extensão .cnf e todos os arquivos usados para configuração do Xref do HTML encontrados serão usados. Você pode configurar a variável de personalização HTMLXREF_MODE para modificar como as referências cruzadas para outras informações de manuais são determinadas. Se HTMLXREF_MODE estiver configurada como ‘file’, o nome do arquivo será usado diretamente como a fonte da informação. Se HTMLXREF_MODE estiver configurada como ‘none’, nenhuma informação será usada. O caso padrão é obtido com HTMLXREF_MODE não definida ou configurada com qualquer outro valor. A variável de personalização HTMLXREF_FILE configura o arquivo usado para configuração do Xref do HTML com um valor diferente do padrão, htmlxref.cnf. Se HTMLXREF_FILE contiver diretórios, eles serão carregados se encontrados, mas não serão pesquisados nos diretórios. Por padrão, o manual distante é considerado estar dividido ou monolítico baseado na divisão do manual sendo produzido. Você pode configurá-lo explicitamente, configurando EXTERNAL_CROSSREF_SPLIT.

Existem também variáveis de personalização que modificam vários outros aspectos das referências cruzadas:

  • Você consegue configurar o nome do arquivo usado para o nó Topo em referências cruzadas por configurando o valor da variável de personalização TOP_NODE_FILE_TARGET; padrão é index.html.
  • Você especifica um diretório base para externos manuais com EXTERNAL_DIR; no caso padrão, não existe nenhum.
  • Similarmente, você configura a extensão do arquivo para referenciar cruzadamente a outros manuais com EXTERNAL_CROSSREF_EXTENSION.

Entretanto, em geral, o uso dessas tornará referências entre manuais “inválidas” no sentido de que a URL gerada não lincará para o manual externo, a menos que esse manual fosse ele próprio produzido usando a personalização correspondente. Portanto, em geral, é melhor usar apenas a Configuração do Xref do HTML.

Você consegue mudar o comprimento máximo de um nome de arquivo base para referências cruzadas internas configurando BASEFILENAME_LENGTH; por padrão, os nomes dos arquivos base são truncados para 245 caracteres.
