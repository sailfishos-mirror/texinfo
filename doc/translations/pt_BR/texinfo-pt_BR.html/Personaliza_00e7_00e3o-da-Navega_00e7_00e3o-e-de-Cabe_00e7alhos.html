22.8.3 Personalização da Navegação e de Cabeçalhos ¶

Cabeçalhos e rodapés com um painel de navegação são gerados no caso padrão. Se você usar --no-headers, ou se a variável de personalização HEADERS estiver desconfigurada, o painel de navegação só será inserido no início dos arquivos divididos.

Por padrão, os elementos <link> são gerados no <head> do HTML para especificar relacionamentos entre a página HTML e outros recursos, por exemplo, o nó Topo, o próximo nó ou o sumário. Desconfigure USE_LINKS para evitar esses elementos.

O <title> e a descrição do documento em <head> são baseados em @settitle (veja-se @settitle: Configura o Título do Documento). Se o manual for dividido, o nome do nó também será adicionado a esse título HTML. Configure SECTION_NAME_IN_TITLE para usar o argumento do comando de estruturamento do capítulo associado em vez do nome do nó.

Por padrão, se uma codificação de entrada for configurada (tipicamente por meio de @documentencoding), essas informações serão usadas para configurar o nome da codificação de saída, caso contrário, a codificação da saída gerada será baseada na codificação padrão. Uma etiqueta ‘<meta>’ é gerada, na seção ‘<head>’ do HTML, para especificar a codificação da saída gerada. Veja-se @documentencoding codificação: Configurar Codificação de Entrada. Para configurar explicitamente a codificação da saída gerada, configure OUTPUT_ENCODING_NAME. A codificação especificada deveria ser um nome de conjunto de caracteres normalizado usável em HTML, tipicamente um dos nomes de codificação preferidos da IANA.

Quando a saída é dividida em nós (veja-se Dividindo HTML), o valor da variável de personalização WORDS_IN_PAGE especifica o comprimento mínimo aproximado da página no qual um painel de navegação é colocado na parte inferior de uma página. Não é possível calibrar esse valor muito precisamente para resultados exatos: isso ocorre porque a contagem de palavras usadas para a verificação é baseada na saída HTML para o nó até o momento (incluindo qualquer barra de navegação na parte superior da página), o que produz um valor um pouco maior que o número de palavras que seriam visíveis para o(a) usuário(a) no navegador da web deles(as).

A aparência do painel de navegação é afetada pelas seguintes variáveis de personalização, todas falsas no caso padrão:

DATE_IN_HEADER ¶

Colocar a data de geração do documento no cabeçalho.

HEADER_IN_TABLE ¶

Usar tabelas para formatação de cabeçalho em vez de um simples <div>.

ICONS ¶

Usar ícones para o painel de navegação.

PROGRAM_NAME_IN_FOOTER ¶

Se configurada, gerar o nome do programa e diversas informações relacionadas nos rodapés das páginas.

VERTICAL_HEAD_NAVIGATION ¶

Se configurada, um painel vertical de navegação é usado.

Configurar-se ICONS é necessário, mas não suficiente para obter ícones para botões de direção, uma vez que nenhuma imagem de botão é especificada no caso padrão. Além disso, você precisa configurar as variáveis de personalização ACTIVE_ICONS e PASSIVE_ICONS. Você só consegue fazer isso usando um arquivo de inicialização (veja-se Invocando texi2any a partir de um Shell). Veja-se Personalização da Saída do texi2any do GNU Texinfo.
