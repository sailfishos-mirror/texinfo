9.2.1 Sintaxe da Imagem ¶

Aqui está a sinopse do comando @image: 

@image{nomearquivo[, largura[, altura[, alttexto[, extensão]]]]}

O argumento nomearquivo é obrigatório, e precisa não ter uma extensão, pois os diferentes processadores suportam formatos diferentes:

  • TeX (saída DVI) lê o arquivo nomearquivo.eps (Formato encapsulado PostScript).
  • TeX (saída PDF) tenta (na ordem) nomearquivo.pdf, nomearquivo.png, nomearquivo.jpg e nomearquivo.jpeg. Ele também tenta as versões em letras maiúsculas das extensões. O formato PDF não suporta imagens EPS, de modo que essas precisam ser convertidas primeiro.
  • No Info, nomearquivo.txt é incluído literalmente (mais ou menos como se estivesse em @verbatim). A saída Info também pode incluir uma referência para nomearquivo.png ou nomearquivo.jpg. (Veja-se abaixo).
  • Em HTML, uma referência para nomearquivo.png, nomearquivo.jpg, nomearquivo.jpeg ou nomearquivo.gif (nessa ordem) é gerada. Se nenhum desses existir, fornece um erro, e gera uma referência para nomearquivo.jpg de qualquer maneira.
  • Em DocBook, todos os seguintes são verificados: nomearquivo.eps, nomearquivo.gif, nomearquivo.jpeg, nomearquivo.jpg, nomearquivo.pdf, nomearquivo.png e nomearquivo.svg. Referências são geradas para cada arquivo encontrado. Também, nomearquivo.txt é incluído literalmente, se presente. (Supõe-se que o processador DocBook subsequente escolha o adequado).
  • Para LaTeX, nomearquivo sem nenhuma extensão é usado; supõe-se que o processador LaTeX subsequente escolha o tipo apropriado de imagem.
  • Para saída Info e HTML, o quinto argumento opcional extensão para @image é usado para a extensão de arquivo, se ele for especificado e o arquivo for encontrado. Qualquer ponto inicial deveria ser incluído em extensão. Por exemplo: 
    @image{foo,,,,.xpm}

Se você quiser instalar arquivos de imagens para uso por leitores Info também, nós recomendamos colocá-los em um subdiretório como ‘foo-figuras’ para um pacote foo. A cópia dos arquivos para $(infodir)/foo-figuras/ deveria ser feita em teu Makefile.

Os argumentos largura e altura estão descritos na próxima seção.

Se uma imagem for a primeira coisa em um parágrafo e seguida por mais texto, então você deveria preceder o comando @image por @indent ou @noindent para indicar o início da formatação do parágrafo. Isso é especialmente importante para saída TeX para obter o recuo correto do parágrafo.

Use @center para centralizar uma imagem (veja-se @titlefont, @center e @sp).

Para saída HTML, o atributo alt para imagens inline é configurado para o (quarto) argumento opcional alttexto para @image, se fornecido. Se não fornecido, o nome completo de arquivo da imagem sendo exibida será usado. O alttexto é processado como texto do Texinfo, de forma que caracteres especiais, tais como ‘"’ e ‘<’ e ‘&’, são escapados na saída gerada HTML; também, você pode obter uma sequência de caracteres alt vazia com @- (um comando que não produz saída; veja-se @- e @hyphenation: Hifenização em Saída Impressa).

Para saída Info, a sequência alttexto também é processada como texto e saída do Texinfo. Nesse caso, ‘\’ é escapada como ‘\\’ e ‘"’ como ‘\"’; outros escapes não são feitos.

Na saída Info, uma referência para o arquivo binário da imagem é escrita (tentando nomearquivo sufixado com extensão, .extensão, .png, ou .jpg, nessa ordem) se um existir. O arquivo .txt também é incluído literalmente, se um existir. Dessa maneira, leitores Info que consigam exibir imagens (tais como o navegador Info do Emacs, executando sob X) podem fazer isso, ao passo que leitores Info que somente consigam usar texto (tais como o leitor autônomo Info) conseguem exibir a versão textual.
