D.10.3 Depuração com TeX ¶

Você também pode capturar erros ao formatar um arquivo com TeX.

Normalmente, você vai querer fazer isso depois de ter executado texinfo-format-buffer (ou, melhor, makeinfo-buffer) sobre o mesmo arquivo, porque texinfo-format-buffer às vezes exibe mensagens de erro que fazem mais sentido que o TeX. (Veja-se Capturando Erros com formatação do Info, para mais informações).

Por exemplo, TeX foi executado sobre um arquivo do Texinfo, parte do qual é mostrado aqui: 

---------- Buffer: texinfo.texi ----------
nome do arquivo Texinfo como extensão.  Os
@samp{??} são `curingas' que fazem com que o shell
substitua todos os arquivos brutos de índice. (@xref{ordenando
indices, para mais informações acerca da ordenação de
indices).
---------- Buffer: texinfo.texi ----------

(A referência cruzada carece de uma chave de fechamento). TeX produziu a seguinte saída, depois da qual parou: 

---------- Buffer: *tex-shell* ----------
Argumento fugitivo?
{ordenando índices, para mais informações acerca de
ordenação de índices). @ETC.
! O parágrafo terminou antes que @xref estivesse completa.
<para ser lido novamente>
                  @par
l.27

?
---------- Buffer: *tex-shell* ----------

Nesse caso, TeX produziu uma mensagem de erro precisa e compreensível: 

O parágrafo terminou antes que @xref estivesse completa.

‘@par’ é um comando interno do TeX sem relevância para o Texinfo. ‘l.27’ significa que TeX detectou o problema na linha 27 do arquivo do Texinfo. O ‘?’ é o prompt que o TeX usa nessa circunstância.

Infelizmente, o TeX nem sempre é tão útil e, às vezes, você precisa realmente ser um Sherlock Holmes para descobrir o que deu errado.

De qualquer forma, se você se deparar com um problema como esse, poderá fazer uma de três coisas.

  1. Você pode dizer ao TeX para continuar executando e ignorar apenas esse erro digitando RET no prompt ‘?’.
  2. Você pode dizer ao TeX para continuar executando e para ignorar todos os erros da melhor maneira possível digitando r RET no prompt ‘?’.

    Essa frequentemente é a melhor coisa a se fazer. No entanto, tenha cuidado: um erro possivelmente produza uma cascata de mensagens adicionais de erro, à medida que as consequências dele forem sentidas ao longo do restante do arquivo. Para parar o TeX quando ele estiver produzindo tal avalanche de mensagens de erro, digite C-c (ou C-c C-c, se você estiver executando um shell dentro do Emacs).

  3. Você pode dizer ao TeX para interromper essa execução digitando x RET no prompt ‘?’.

Se estiver executando o TeX dentro do Emacs, você precisará comutar para o buffer do shell e a linha na qual o TeX oferece o prompt ‘?’.

Às vezes, o TeX formatará um arquivo sem produzir mensagens de erro, mesmo que exista um problema. Isso geralmente ocorre se um comando não for finalizado, mas o TeX puder, de qualquer maneira, continuar o processamento. Por exemplo, se você falhar para finalizar uma lista detalhada com o comando @end itemize, o TeX escreverá um arquivo DVI que você conseguirá imprimir. A única mensagem de erro que o TeX lhe dará será o comentário um tanto misterioso: 

(@end ocorreu dentro de um grupo no nível 1)

No entanto, se você imprimir o arquivo DVI, descobrirá que o texto do arquivo que segue a lista detalhada estará inteiramente recuado como se fosse parte do último item da lista detalhada. A mensagem de erro é a maneira como o TeX diz que esperava encontrar um comando @end em algum lugar no arquivo; mas não conseguiu determinar onde era necessário.

Outra fonte de erros notoriamente difíceis de encontrar é um comando @end group ausente. Se você ficar perplexo(a) com erros incompreensíveis, procure primeiro um comando @end group ausente.

Se o arquivo do Texinfo carecer de linhas de cabeçalho, TeX poderá parar no início da execução dele e exibir uma saída que se parece com à seguinte. O ‘*’ indica que TeX está aguardando entrada. 

Este é o TeX, versão 3.14159 (Web2c 7.0)
(test.texinfo [1])
*

Nesse caso, simplesmente digite \end RET depois do asterisco. Em seguida, escreva as linhas de cabeçalho no arquivo do Texinfo e execute o comando TeX novamente. (Observe o uso da barra invertida, ‘\’. TeX usa ‘\’ em vez de ‘@’; e nessa circunstância, você está trabalhando diretamente com TeX, não com Texinfo).
