D.10.2 Capturando Erros com formatação do Info ¶

Depois de ter escrito parte de um arquivo do Texinfo, você consegue usar o comando texinfo-format-region ou o makeinfo-region para ver se a região formata corretamente.

Provavelmente, entretanto, você está lendo esta seção porque, por algum motivo, não pode usar o comando makeinfo-region; portanto, o restante desta seção presume que você está usando texinfo-format-region.

Se você tiver cometido um erro com um comando @, texinfo-format-region parará o processamento no momento ou depois do erro e exibirá uma mensagem de erro. Para ver onde no buffer o ocorreu o erro, comute para o buffer ‘*Info Region*’; o cursor estará em uma posição que é posterior ao local do erro. Além disso, o texto não será formatado após o local onde o erro ocorreu (ou mais precisamente, onde ele foi detectado).

Por exemplo, se acidentalmente encerrar um menu com o comando @end menus com um ‘s’ no final, em vez de @end menu, você verá uma mensagem de erro que diz: 

@end menus não é manuseado pelo texinfo

O cursor parará no ponto no buffer onde o erro ocorrer, ou não muito depois dele. O buffer se parecerá com isto: 

---------- Buffer: *Info Region* ----------
* Menu:

* Usando texinfo-show-structure:: Como usar
                                  `texinfo-show-structure'
                                  para capturar erros.
* Executando Info-validate::      Como verificar se existem
                                  nós não referenciados.
@end menus
∗
---------- Buffer: *Info Region* ----------

O comando texinfo-format-region às vezes fornece mensagens de erro um pouco estranhas. Por exemplo, a seguinte referência cruzada falha para formatar: 

(@xref{Capturando Erros, para mais informações).

Neste caso, texinfo-format-region detecta a chave de fechamento ausente, mas exibe uma mensagem que diz ‘Parênteses não balanceados’ em vez de ‘Chaves não balanceadas’. Isso ocorre porque o comando de formatação procura descorrespondências entre chaves como se elas fossem parênteses.

Às vezes, texinfo-format-region falha para detectar erros. Por exemplo, a seguir, a chave de fechamento é trocada pelo parêntese de fechamento: 

(@xref{Capturando Erros), para mais informações.}

A formatação produz: 

(*Observação para mais informações: Capturando Erros)

A única maneira para você detectar esse erro é a de perceber que a referência deveria ter se parecido com isto: 

(*Observe Capturando Erros::, para mais informações).

Aliás, se estiver lendo este nó no Info e digitar f RET (Info-follow-reference), você gerará uma mensagem de erro que diz: 

Esse nó não existe: "Capturando Erros) A única maneira ...

Isso ocorre porque o Info percebe o exemplo do erro como a primeira referência cruzada neste nó e se você digitasse um RET imediatamente depois de digitar o comando f do Info, o Info tentará ir para o nó referenciado. Se você digitasse f catch TAB RET, o Info completará o nome do nó do exemplo escrito corretamente e te levará ao nó ‘Capturando Erros’. (Se você tentar isso, poderá retornar do nó ‘Capturando Erros’ digitando l (Info-last)).
