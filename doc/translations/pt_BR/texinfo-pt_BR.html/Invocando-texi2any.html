20.1 Invocando texi2any a partir de um Shell ¶

Para processar um arquivo do Texinfo, invoque texi2any seguido pelo nome do arquivo do Texinfo. Selecione também o formato que você quer produzir com a opção de linha de comando apropriada (o padrão é Info). Assim, para criar o arquivo Info para Bison, digite o seguinte para o shell: 

texi2any --info bison.texi

Você consegue especificar mais que um nome de arquivo de entrada; cada um é processado em sequência. Se um nome de arquivo de entrada for ‘-’, a entrada padrão será lida.

O programa texi2any aceita muitas opções. Talvez as mais básicos sejam aquelas que mudam o formato da saída gerada. Por padrão, texi2any produz Info.

Cada opção de linha de comando ou é um nome longo precedido por ‘--’ ou é uma única letra precedida por ‘-’. Você pode usar abreviações para os nomes longos de opções, desde que elas sejam únicas.

Por exemplo, você poderia usar o seguinte comando de shell para criar um arquivo Info para bison.texi no qual as linhas fossem preenchidas em somente 68 colunas: 

texi2any --fill-column=68 bison.texi

Você pode escrever duas ou mais opções em sequência, assim: 

texi2any --no-split --fill-column=70 ...

(Isso manteria o arquivo Info unido como um arquivo possivelmente muito longo e também configuraria a coluna de preenchimento como 70).

As opções são (aproximadamente em ordem alfabética):

--commands-in-node-names ¶

Essa opção agora não faz nada, mas permanece para compatibilidade. (Ela costumava garantir que os comandos @ nos nomes dos nós fossem expandidos por todo o documento, especialmente @value. Isso agora é feito por padrão).

--conf-dir=dir ¶

Posponha dir à lista de pesquisa de diretórios para encontrar arquivos de personalização que podem ser carregados com --init-file (veja-se abaixo). O valor de dir pode ser um único diretório ou uma lista de vários diretórios separados pelo caractere usual de separador de caminho (‘:’ em sistemas do tipo Unix, ‘;’ no Windows).

--css-include=arquivo ¶

Ao produzir HTML, inclui literalmente o conteúdo de arquivo, que deveria conter especificações de folhas de estilos em cascata, no bloco ‘<style>’ da saída gerada HTML. Se arquivo for ‘-’, lê a entrada padrão. Veja-se CSS do HTML.

--css-ref=url ¶

Ao produzir HTML, adiciona uma etiqueta ‘<link>’ à saída que referencia uma folha de estilo em cascata em url. Isso permite usar folhas de estilo independentes.

-D var ¶
-D 'var valor'

Faz com que a variável var do Texinfo seja definida. Isso é equivalente a @set var no arquivo do Texinfo (veja-se Sinalizadores: @set, @clear, condicionais e @value).

O argumento para a opção é sempre uma palavra para o shell; se ela contiver espaços em branco internos, a primeira palavra será considerada como o nome da variável e o restante como o valor. Por exemplo, -D 'minhavar algumvalor' é equivalente a @set minhavar algumvalor.

--docbook ¶

Gera saída DocBook (em vez de Info).

--document-language=idioma ¶

Use idioma para traduzir palavras-chave Texinfo que acabam no documento de saída. O padrão é a localidade especificada pelo comando @documentlanguage, se houver, caso contrário, inglês (veja-se @documentlanguage ll[_cc]: Configurar o Idioma do Documento).

--dvi ¶

Gere um arquivo DVI do TeX usando texi2dvi, em vez de Info (veja-se Saída Impressa do texi2any).

--dvipdf ¶

Gere um arquivo PDF usando texi2dvi --dvipdf, em vez de Info (veja-se Saída Impressa do texi2any).

--enable-encoding ¶
--disable-encoding

Por padrão, ou com --enable-encoding, produza caracteres acentuados e especiais em saída Info e de texto simples com base na codificação do documento. Com --disable-encoding, transliterações ASCII de 7 bits são geradas. Também obedecido em outros formatos de saída para ordenação de chaves de índice e para alguma saída de texto simples.

--epub3 ¶

Gerar saída EPUB 3

--error-limit=limite ¶
-e limite

Informar limite de erros antes de abortar (supondo que continuar seria inútil); padrão 100.

--fill-column=largura ¶
-f largura

Especificar o número máximo de colunas em uma linha; isso é a borda direita de uma linha. Os parágrafos que sejam preenchidos serão preenchidos com essa largura. (Preencher é o processo de quebrar e de conectar linhas para que as linhas sejam do mesmo comprimento, ou menores, que o número especificado como a coluna de preenchimento. As linhas são quebradas entre as palavras). O valor padrão é 72.

--footnote-style=estilo ¶
-s estilo

Configurar o estilo da nota de rodapé como estilo: ‘end’ para o estilo do nó final (o padrão) ou ‘separate’ para o estilo do nó separado. O valor configurado por essa opção substitui o valor configurado em um arquivo do Texinfo por um comando @footnotestyle (veja-se Estilos de Notas de Rodapé).

No Info, quando o estilo da nota de rodapé for ‘separate’, texi2any cria um novo nó contendo as notas de rodapé encontradas no nó atual. Quando o estilo da nota de rodapé for ‘end’, texi2any coloca as referências da nota de rodapé no final do nó atual.

No HTML, quando o estilo da nota de rodapé for ‘end’, ou se a saída gerada não for dividida, as notas de rodapé são colocadas no final da saída gerada. Se configurada como ‘separate’ e a saída gerada for dividida, elas serão colocadas em um arquivo separado.

--force ¶
-F

Normalmente, se o arquivo de entrada contiver erros, os arquivos de saída não serão criados. Com essa opção, eles são preservados.

--help ¶
-h

Imprimir uma mensagem com as opções disponíveis e uso básico, então sair com sucesso.

--html ¶

Gerar saída HTML (em vez de Info). Por padrão, a saída gerada HTML é dividida em um arquivo de saída por nó e a saída gerada dividida é escrita em um subdiretório baseado no nome do arquivo de entrada. Veja-se Gerando HTML.

-I diretório ¶

Posponha diretório à lista de pesquisa de diretório para encontrar arquivos que sejam incluídos usando o comando @include. Por padrão, texi2any pesquisa o diretório atual e o diretório principal do caminho do arquivo de entrada, se existir um (e não for o diretório atual). O valor de diretório pode ser um diretório ou uma lista de vários diretórios separados pelo caractere separador de caminho usual (‘:’ em sistemas do tipo Unix, ‘;’ no Windows).

--ifdocbook ¶
--ifhtml
--ifinfo
--iflatex
--ifplaintext
--iftex
--ifxml

Para o formato fornecido, processar os comandos ‘@ifformato’ e ‘@formato’ e não processar ‘@ifnotformato’, independentemente do formato sendo gerado. Por exemplo, se --iftex for fornecido, então os blocos ‘@iftex’ e ‘@tex’ serão lidos e os blocos ‘@ifnottex’ serão ignorados.

--no-ifdocbook ¶
--no-ifhtml
--no-ifinfo
--no-iflatex
--no-ifplaintext
--no-iftex
--no-ifxml

Para o formato fornecido, não processar os comandos ‘@ifformato’ e ‘@formato’ e processar ‘@ifnotformato’, independentemente do formato sendo gerado. Por exemplo, se --no-ifhtml for fornecido, então blocos ‘@ifhtml’ e ‘@html’ não serão lidos, e blocos ‘@ifnothtml’ serão.

--info ¶

Gerar saída Info. Por padrão, se o arquivo da saída gerada contiver mais que cerca de 300.000 bytes, ele será dividido em subarquivos mais curtos de aproximadamente esse tamanho. O nome do arquivo da saída gerada e de quaisquer subarquivos é determinado pelo nome do arquivo de entrada ou por @setfilename, se presente (veja-se Configurando o Nome do Arquivo da Saída Gerada). Veja-se Arquivos de Etiqueta e Arquivos Divididos.

--init-file=arquivo ¶

Carregar arquivo como código para modificar o comportamento e a saída do manual gerado. É comum usar as extensões .pm ou .init para esses arquivos de personalização, mas isso não é obrigatório; o nome de arquivo pode ser qualquer coisa. A opção --conf-dir (veja-se acima) pode ser usada para adicionar à lista de diretórios nos quais esses arquivos de personalização são pesquisados.

--internal-links=arquivo ¶

No modo HTML, produzir um arquivo separado por tabulações contendo três colunas: o linque interno para um item, o tipo do item e o nome do item ou o termo correspondente ao item que foi indexado ou inserido.

Os itens gerados são:

unidades de saída gerada

As unidades de saída são a unidade principal dos documentos de saída. As unidades de saída contêm o conteúdo associado a um nó ou a um comando de seccionamento. O nome do item é o nó associado ou um nome de comando de seccionamento.

Comandos de seccionamento

O nome do comando sem @, ajustado para elevar/rebaixar seções é posposto ao nome do item.

nós, âncoras e flutuadores

O tipo do elemento é o nome do comando sem @.

intradas de índice

O tipo do elemento é o nome do índice.

Os itens estão na ordem de classificação natural para o elemento fornecido. Esse despejo pode ser útil para pós-processadores.

--latex ¶

Gerar saída LaTeX

--macro-expand=arquivo ¶
-E arquivo

Gerar o fonte do Texinfo, com todas as macros do Texinfo expandidas, para arquivo. Normalmente, o resultado da expansão de macro é usado internamente por texi2any e então descartado.

--no-headers ¶

Não incluir menus ou linhas separadoras de nós na saída gerada.

Ao gerar Info, isso é o mesmo que usar --plaintext, resultando em um arquivo de texto simples. Além disso, a saída gerada é a saída padrão, a menos que substituída por -o. (Esse comportamento é para retro compatibilidade).

Ao gerar HTML e a saída gerada for dividida, gerar também linques de navegação somente no início de cada arquivo. Se a saída gerada não for dividida, não incluir linques de navegação no topo de cada nó em absoluto. Veja-se Gerando HTML.

--node-files ¶
--no-node-files

Com --node-files, ao gerar HTML, criar arquivos de redirecionamento para âncoras e quaisquer nós ainda não gerados com o nome do arquivo correspondente ao nome do nó (veja-se Expansão de Nome de Nó de Referência Cruzada do HTML). Isso torna possível o êxito de referências entre manuais em nível de seção e de capítulo (veja-se Configuração de Referência Cruzada do HTML).

Se a saída gerada for dividida, isso estará habilitado por padrão. Se a saída gerada não for dividida, --node-files habilita a criação dos arquivos de redirecionamento, além do arquivo de saída principal monolítico. --no-node-files suprime a criação de arquivos de redirecionamento em qualquer caso. Essa opção não tem efeito com nenhum formato de saída diferente do HTML. Veja-se Gerando HTML.

--no-validate ¶
--no-pointer-validate

Suprimir a fase de validação de ponteiro do texi2any—uma coisa perigosa de se fazer. Isso também pode ser feito com o comando @novalidate (veja-se Formatando Documentos Parciais).

Se você não suprimir a validação de ponteiro, texi2any verificará a validade das referências cruzadas e entradas de menu no arquivo Texinfo, bem como dos ponteiros de nó, se eles(as) forem fornecidos(as) explicitamente.

--no-warn ¶

Suprimir mensagens de aviso (porém não mensagens de erro).

--number-footnotes ¶
--no-number-footnotes

Com --no-number-footnotes, suprimir a numeração automática de notas de rodapé. Por padrão, notas de rodapé são numeradas sequencialmente dentro de um nó, ou seja, o número da nota de rodapé atual é reconfigurado para 1 no início de cada nó.

--number-sections ¶
--no-number-sections

Com --number-sections (o padrão), produzir números de capítulo, seção e apêndice como em manuais impressos. Isso funciona somente com manuais estruturados hierarquicamente. Você deveria especificar --no-number-sections se teu manual não for normalmente estruturado.

--output=file ¶
-o arquivo

Especificar que a saída gerada deveria ser direcionada para arquivo. Isso substitui qualquer nome de arquivo especificado em um comando @setfilename encontrado no fonte do Texinfo. Se nem @setfilename nem essa opção forem especificados, o nome do arquivo de entrada será usado para determinar o nome da saída gerada. Veja-se Configurando o Nome do Arquivo da Saída Gerada.

Se arquivo for ‘-’, a saída gerada vai para a saída padrão e ‘--no-split’ estará implícita.

Se arquivo for um diretório ou terminar com uma ‘/’, as regras usuais serão usadas para determinar o nome do arquivo de saída (ou seja, usar @setfilename ou o nome do arquivo de entrada), mas os arquivos serão escritos no diretório arquivo. Por exemplo, ‘texi2any -o bar/ foo.texi’, com ou sem --no-split, escreverá bar/foo.info, e possivelmente outros arquivos, sob bar/.

Ao gerar HTML e a saída gerada for dividida, arquivo será usado como o nome para o diretório no qual todos os arquivos serão escritos. Por exemplo, ‘texi2any -o bar --html foo.texi’ escreverá bar/index.html, entre outros arquivos.

Ao gerar EPUB, um diretório contêiner para os arquivos e diretórios necessários para o formato EPUB será criado, bem como o arquivo de saída gerada EPUB. Se arquivo corresponder a um diretório, o diretório contêiner será colocado dentro de arquivo. O arquivo de saída gerada EPUB nunca é colocado nesse diretório. Se arquivo corresponder a um arquivo, ele será usado para o nome do arquivo de saída gerada EPUB.

--output-indent=valor ¶

Essa opção agora não faz nada, mas permanece para compatibilidade. (É usada para alterar o recuo na saída gerada XML/DocBook).

-P caminho ¶

Posponha caminho à lista de pesquisa de diretórios para @include. Veja-se ‘-I’ acima.

--paragraph-indent=recuo ¶
-p recuo

Configurar o estilo de recuo do parágrafo para recuo. O valor configurado por essa opção substitui o valor configurado em um arquivo do Texinfo por um comando @paragraphindent (veja-se @paragraphindent: Controlando Recuo do Parágrafo). O valor de recuo é interpretado conforme segue:

‘asis’

Preservar qualquer recuo existente (ou falta dele) no início dos parágrafos.

‘0’ ou ‘none’

Deletar qualquer recuo existente.

num

Recuar cada parágrafo com num espaços.

O padrão é o de recuar dois espaços, exceto para parágrafos após o título de uma seção, os quais não são recuados.

--pdf ¶

Gerar um arquivo PDF usando texi2dvi --pdf, em vez de Info (veja-se Saída Impressa do texi2any).

--plaintext ¶

Produzir um arquivo de texto simples (em vez de Info): não incluir menus ou linhas separadoras de nós na saída gerada. Isso resulta em um arquivo de texto simples que você consegue (por exemplo) enviar por correio eletrônico sem complicações ou incluir em uma distribuição (por exemplo, um arquivo INSTALL).

Com essa opção, a saída gerada vai para a saída padrão por padrão, em vez de para um arquivo com um nome baseado no nome do arquivo de entrada ou @setfilename; isso pode ser substituído por -o.

--ps ¶

Gerar um arquivo PostScript usando texi2dvi --ps, em vez de Info (veja-se Saída Impressa do texi2any).

--set-customization-variable variável=valor ¶
-c variável=valor

Configurar a variável de personalização variável como valor. O = é opcional, mas tanto variável quanto valor precisam estar aspeados para o shell conforme necessário para que o resultado seja uma palavra. Muitos aspectos do comportamento e saída do texi2any podem ser controlados por variáveis de personalização, além do que pode ser configurados no documento pelos comandos @ e com outras chaves de linha de comando. Veja-se Variáveis de Personalização.

--split=como ¶
--no-split

Ao gerar Info, por padrão, grandes arquivos de saída são divididos em subarquivos menores, de aproximadamente 300k bytes. Ao gerar HTML, por padrão, cada arquivo de saída contém um nó (veja-se Gerando HTML). --no-split suprime essa divisão da saída.

Alternativamente, --split=como pode ser usada para especificar em qual nível a saída HTML deveria ser dividida. Os valores possíveis para como são:

‘chapter’

A saída gerada é dividida em @chapter e outros comandos @ de seccionamento nesse nível (@appendix, entre outros).

‘section’

A saída gerada é dividida em @section e semelhante.

‘nó’

A saída gerada é dividida em cada nó. Esse é o padrão.

A saída gerada de texto simples pode ser dividida semelhante ao HTML. Isso possivelmente seja útil para extrair seções a partir de um documento do Texinfo e disponibilizá-las como arquivos separados.

--split-size=número ¶

Manter arquivos Info com no máximo número caracteres, se possível; o padrão é 300.000. (No entanto, um nó nunca será dividido entre arquivos Info).

--trace-includes ¶

Imprimir o nome de cada arquivo incluído na saída padrão, incluindo quaisquer arquivos incluídos indiretamente. Um arquivo de inclusão será impresso somente se for realmente encontrado. Quando essa opção é fornecida, texi2any não gera em nenhum formato de saída. (O objetivo dessa opção é o de facilitar coletar os fontes de um manual do Texinfo).

--transliterate-file-names ¶

Habilitar transliteração de caracteres não ASCII em nomes de comandos de nó e de seccionamento para fins de criação de identificadores de nomes de arquivos e de comandos de seccionamento. Os nomes de arquivos e identificadores obtidos dessa maneira são dependentes da plataforma e do processador. Veja-se Expansão do Caractere de 8 Bits da Referência Cruzada do HTML.

Arquivos de redirecionamento para âncoras e nós não são afetados, portanto, se --node-files estiver habilitada, arquivos com nomes não transliterados também serão criados. É recomendado criar nomes de arquivos não transliterados para nós, de modo que as referências cruzadas para o manual gerado sejam bem-sucedidas. Veja-se --node-files. Veja-se Configuração de Referência Cruzada do HTML.

-U variável

Faz com que variável seja indefinida. Isso é equivalente a @clear variável no arquivo do Texinfo (veja-se Sinalizadores: @set, @clear, condicionais e @value).

--verbose ¶

Faz com que texi2any exiba mensagens dizendo o que está fazendo. Normalmente, texi2any só gera mensagens se existirem erros ou avisos.

--version ¶
-V

Imprimir o número da versão, então sair com sucesso.

--Xopt sequência ¶

Passar sequência (uma palavra de shell) para texi2dvi; pode ser repetido (veja-se Saída Impressa do texi2any).

--xml ¶

Gerar saída XML do Texinfo (em vez do Info).
