20.2 Variáveis de Ambiente Reconhecidas pelo texi2any ¶

texi2any também lê a variável de ambiente TEXINFO_OUTPUT_FORMAT para determinar o formato da saída gerada, se não substituída por uma opção de linha de comando. O valor deveria ser um de: 

docbook  dvi  dvipdf  epub3  html  info  latex  pdf  plaintext  ps  xml

Se não configurada ou especificada de outro modo, saída Info é o padrão.

TEXINFO_OUTPUT_FORMAT pode assumir alguns outros valores especiais, os quais não correspondem a nenhum formato de saída configurável de linha de comando (veja-se Seleção do Formato de Saída).

A variável de personalização de mesmo nome também é lida; se configurada, essa substitui uma configuração de variável de ambiente, mas não uma opção de linha de comando. Veja-se Seleção do Formato de Saída.

Você consegue controlar o uso de módulos de extensão Perl da implementação Perl do texi2any configurando a variável de ambiente TEXINFO_XS. Esses módulos são código nativo compilado que o código interpretado da Perl consegue usar. Idealmente, esses módulos de extensão deveriam simplesmente funcionar, e a única diferença notável que eles deveriam fazer é que texi2any terminasse de executar mais cedo. No entanto, você consegue usar essa variável de ambiente para fins de solução de problemas: por exemplo, se tiver problemas com a saída gerada do texi2any variando, dependendo se os módulos de extensão estiverem em uso.

Os seguintes valores da TEXINFO_XS são reconhecidos pelo texi2any:

‘default’

O comportamento padrão. Tentar carregar módulos de extensão e voltar silenciosamente para as implementações interpretadas da Perl se isso falhar.

‘warn’

Tentar carregar módulos de extensão e, se isso falhar, fornecer uma mensagem de aviso antes de voltar para as implementações interpretadas da Perl.

‘required’

Tentar carregar módulos de extensão e, se isso falhar, fornecer uma mensagem e abortar.

‘debug’

Tentar carregar módulos de extensão, imprimindo muitas mensagens ao fazer isso.

‘omit’

Não usar módulos de extensão.

Você pode desabilitar o uso da implementação de código nativo na implementação Perl do texi2any para as principais etapas de processamento mais detalhadamente. Se os módulos de código nativo não forem usados em uma etapa, eles não poderão ser usados nas etapas seguintes. São distinguidas três etapas, cada uma associada a uma variável de ambiente:

parsing ¶

Corresponde à conversão da entrada do Texinfo em um formato interno de árvore usado para processamento posterior. Configure TEXINFO_XS_PARSER como ‘0’ para desabilitar o uso da implementação de código nativo do módulo analisador.

structure ¶

Corresponde à determinação de seccionamentos e de estruturas de nós. Configure TEXINFO_XS_STRUCTURE como ‘0’ para desabilitar o uso da implementação de código nativo de módulos Perl nessa etapa.

conversion ¶

Configure TEXINFO_XS_CONVERT como ‘0’ para desabilitar o uso do código nativo para conversão da árvore para o formato de saída. Observe que muitos formatos de saída não têm uma implementação de código nativo para essa etapa.

Isso pode ser útil para contornar defeitos ou incompatibilidades entre a implementação do código nativo e a implementação em código Perl puro.

A implementação C do texi2any usa somente código nativo para as etapas de análise e de estruturação. Para a etapa de conversão, o código nativo é usado, se possível. Se o código Perl for chamado, o programa sempre tenta carregar os módulos de extensão Perl disponíveis. A falha ao carregar uma extensão será informada e o programa aborta. Configurar-se TEXINFO_XS como debug ainda pode ser útil para obter mais informações. Configurar-se TEXINFO_XS como omit com a implementação C do texi2any é um erro.

Você pode controlar o uso do Perl embutido da implementação C do texi2any configurando a variável de ambiente TEXINFO_C_EMBED_PERL como ‘0’ para desabilitar o uso do Perl embutido. Configure com cuidado, pois os arquivos de inicialização de personalização do HTML, a conversão para a maioria dos formatos de saída e a ordenação ideal do índice exigem Perl.
