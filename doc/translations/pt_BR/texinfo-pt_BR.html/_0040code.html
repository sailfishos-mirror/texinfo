6.1.2 @code{código-amostra} ¶

Use o comando @code para indicar texto que seja um pedaço de um programa e que consiste de tokens sintáticos inteiros. Coloque o texto entre chaves.

Assim, você deveria usar @code para uma expressão em um programa, para o nome de uma variável ou função usada em um programa ou para uma palavra chave em uma linguagem de programação.

Use @code para nomes de comando em linguagens que remontam linguagens de programação, como Texinfo. Por exemplo, @code e @samp são produzidos escrevendo-se ‘@code{@@code}’ e ‘@code{@@samp}’ no fonte Texinfo, respectivamente.

É incorreto alterar a primeira letra de uma palavra dentro de um comando @code quando ele aparecer no início de uma frase. A maioria das linguagens de programação diferencia maiúsculas de minúsculas. Em C, por exemplo, Printf é diferente do identificador printf, e possivelmente seja um erro de ortografia. Mesmo em linguagens que não diferenciam maiúsculas de minúsculas, é confuso para um(a) leitor(a) humano(a) ver identificadores escritos de diferentes maneiras. Escolha uma grafia e sempre a use. Se não quiser iniciar uma frase com um nome de comando escrito todo em letras minúsculas, você deveria reorganizar a frase.

O argumento @code é tipografado em uma fonte de máquina de escrever (mono espaçada). Por exemplo, 

A função retorna @code{nulo}.

produz isto:

A função retorna nulo.

Aqui estão alguns casos para os quais é preferível não se usar @code:

  • Para nomes de comando de shell, como ls (use @command).
  • Para variáveis de ambiente, como TEXINPUTS (use @env).
  • Para opções de shell, como ‘-c’, quando tais opções sejam independentes (use @option).
  • Um comando inteiro de shell frequentemente parece melhor se escrito usando-se @samp em vez de @code. Nesse caso, a regra é escolher o formato mais agradável.
  • Para uma sequência de caracteres menor que um token sintático. Por exemplo, se estiver escrevendo acerca de ‘goto-ch’, que apenas é parte do nome para a função goto-char da Emacs Lisp, você deveria usar @samp.
  • Em geral, quando escrever acerca dos caracteres usados em um token; por exemplo, não use @code quando estiver explicando quais letras ou símbolos imprimíveis podem ser usados nos nomes das funções. (Use @samp). Ainda, você não deveria usar @code para marcar texto que seja considerado entrada para programas, a menos que a entrada seja escrita em uma linguagem que seja semelhante a uma linguagem de programação. Por exemplo, você não deveria usar @code para os comandos de toques de teclas do GNU Emacs (use @kbd em vez disso), embora você possa usar @code para os nomes das funções da Emacs Lisp que os comandos de toques de teclas invocam.

Por padrão, TeX considerará quebrar linhas nos caracteres ‘-’ e ‘_’ dentro do @code e comandos relacionados. Isso pode ser controlado com @allowcodebreaks (veja-se @allowcodebreaks: Controle Quebras de Linha no @code). Na saída gerada HTML, quebrar linhas depende inteiramente do comportamento do navegador. Para Info, parece melhor nunca fazer tais quebras.

Para Info e texto simples, as aspas normalmente são geradas em torno da saída gerada do comando @code e comandos relacionados (por exemplo, @kbd, @command), exceto em contextos tipo máquina de escrever, como o ambiente @example (veja-se @example: Texto de Exemplo) e o @code em si, etc. Para controlar quais aspas são inseridas por texi2any na saída gerada do ‘@code’, etc., vejam-se as variáveis de personalização OPEN_QUOTE_SYMBOL e CLOSE_QUOTE_SYMBOL (veja-se Variáveis de Personalização para Múltiplos Formatos).
